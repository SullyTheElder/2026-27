Your mission

You work for Meridian Analytics, a fictional company. A staff member named Priya reports that her account on the company's HR portal was used by someone else, even though she never shared her password. Your job is to rebuild how it happened: put the attack's events in order, then find the exact step where her credentials were stolen.

Background: what DNS does

People type names like hr.meridian-analytics.example, but computers deliver data using IP addresses. The domain name system (DNS) is the lookup service that connects the two. A DNS server stores DNS records. Each record pairs a name with an IP address. When you type a name, your device asks a DNS server, and the answer tells your browser where to go.

Background: how the attack works

In a DNS poisoning attack, an adversary pretends to be an authoritative name server (NS), meaning an official source for a domain's records. The adversary plants a fake DNS record on a DNS server. Now, when someone looks up the real name, the server hands back the adversary's IP address, and the browser lands on a malicious website.

If that website is a fake login page that looks just like the real one, the adversary can carry out credential harvesting: people type their real credentials into the fake page, and the adversary captures and uses them.

Key idea: poisoning is how the adversary redirects people. Harvesting is how the adversary collects the credentials. They are two different parts of the same chain.
