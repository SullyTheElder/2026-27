Before you start

This is a simulation. Everything here is a made-up network running in your browser. No real packets are sent, and nothing touches the school network. Attacking real networks without permission is illegal.

You will play out an ARP poisoning attack on the fictional network of Meridian Analytics, answering questions as you go. There are five stages. You can retry any question; your first try is what counts toward your accuracy score. This activity is completion-graded: finish every stage and submit the PDF.

Stage 1: Normal operation

The file server is sending a reply meant for Priya's laptop (192.168.1.20). Press the button and watch where the gateway delivers it.

Stage 2: The adversary lies to the gateway

An unknown device has joined the guest network. Its MAC address ends in EE. Press the button to have it send a falsified ARP packet to the gateway (simulated).

Stage 3: Traffic gets redirected

The server sends another reply meant for Priya. Run it twice: once with the adversary forwarding traffic on to Priya, once with forwarding turned off.

To continue: run it once with forwarding ON and once with it OFF, and answer both questions correctly.

Stage 4: What can the adversary do?

The adversary is now sitting between the server and Priya. Try each action on the copy of the reply that passes through its device. The reply contains Priya's file: Q3_Budget.xlsx.

To continue: try both actions and answer both questions correctly.

Stage 5: Name the terms

Match each description to the correct term. Remember: one term is the method, one is the fake identity, and one is the result.

Takeaways

ARP poisoning modifies the gateway's table so the target's IP pairs with the adversary's MAC. MAC spoofing is faking a MAC address. An on-path attack puts the adversary between two parties who both think they're talking directly. Triage first: copying data hurts confidentiality, altering it hurts integrity.
